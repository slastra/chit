# chit design

This is the contract between the server, `chitd`, and the Android and Wear apps. Change it
here first, then in code.

## Pieces

| Piece | What it is |
|---|---|
| `chit-server` | PocketBase embedded as a library, plus the sync routes below |
| `chitd` | Desk daemon: SQLite replica, unix socket, SSE client, reminder timers |
| `chit` | CLI that talks to `chitd` |
| `chit-android` | Phone and Wear apps sharing one Kotlin sync module |

PocketBase owns accounts, the admin UI, file storage and backups. Clients do **not** use
PocketBase's record CRUD or its realtime API for notes. PocketBase realtime has no replay,
so a client that was offline would miss changes. Everything note-shaped moves through the
op log.

## Data model

Collections are defined in `migrations/`.

| Collection | Shared or per user | Fields |
|---|---|---|
| `notes` | shared | owner, kind (`text`, `list`), title, body, color, trashed, deleted |
| `items` | shared | note, text, checked, order, indent (0 or 1), deleted |
| `note_members` | shared | note, user, role (`editor`, `viewer`) |
| `note_state` | per user | note, user, pinned, archived, labels, reminder, reminder_done |
| `labels` | per user | user, name, deleted |

This split matches Keep. Collaborators share the content and color. Each person pins,
archives, labels and sets reminders on their own.

Records are never hard-deleted by sync. `deleted` is a tombstone so the deletion itself can
replicate. Compaction purges old tombstones later.

Record ids are generated by clients, so a note made offline already has its final id. They
use PocketBase's format: 15 characters from `[a-z0-9]`.

## Clocks and merging

Every synced record carries `clocks`, a JSON object mapping field name to the hybrid
logical clock (HLC) of that field's last write:

```json
{"text": "1795692999119-0003-k3j9x2", "checked": "1795692999412-0000-p0a7m1"}
```

An HLC string is `<unix ms, 13 digits>-<counter, 4 hex digits>-<device id>`, so plain
string comparison orders them. A write to a field applies only if its HLC is greater than
the stored one. Otherwise it is dropped, and the sender learns the winning value from the
feed.

Each checklist item is its own record, so concurrent check-offs never collide. Order uses
fractional index keys (`order`), so moving an item rewrites one field. Two offline edits
to the same note body resolve to the later write.

## Sync routes (planned)

All routes need a user token (`Authorization: Bearer <token>` from PocketBase auth).

### `POST /api/chit/ops`

The body is a batch of ops:

```json
{"device": "k3j9x2", "ops": [
  {"collection": "items", "id": "…", "field": "checked", "value": true, "hlc": "…"}
]}
```

The server checks the caller may write each target (owner or `editor` member for shared
collections, self for per-user ones), applies the ops that win, assigns each one a server
sequence number, and appends it to the change log. The response returns the highest
sequence number.

### `GET /api/chit/changes?since=N`

Returns the changes after `N` that are visible to the caller. When a user is added to a
note, the server appends a snapshot of that note to their feed, so a plain catch-up
includes it.

### `GET /api/chit/stream` (SSE)

The same feed, live. Each event's `id` is the sequence number. A client reconnects with
`Last-Event-ID` and gets the replay, then live events.

```
id: 1234
event: op
data: {"collection":"items","id":"…","field":"checked","value":true,"hlc":"…","by":"…"}

: ping

event: reset
data: {}
```

- `: ping` every 45 to 60 s. A client that misses two treats the stream as dead and
  reconnects.
- `reset` means `Last-Event-ID` is older than the compacted log. The client then does a
  full resync.
- The device that sent an op does not get it echoed back.

## Notifications

There is no push service: no FCM, no ntfy.

- **Reminders** are scheduled on each device from its replica: `AlarmManager.setAlarmClock`
  on the phone, timers in `chitd` that become lastshell toasts. The watch schedules nothing.
  It shows the phone's mirrored notification, whose actions run on the phone. Marking a
  reminder done syncs `reminder_done`, and every device cancels its alarm or notification.
- **Shared-note activity** reaches a phone through a `remoteMessaging` foreground service
  holding the SSE stream, with a battery optimization exemption. A WorkManager sync every
  15 minutes is the fallback.
